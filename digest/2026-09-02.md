## AI Security (3)

### [Will the User Ever Know? Covert Indirect Prompt Injection Attacks on Tool-Using LLM Agents](https://arxiv.org/abs/2608.30362)
*arXiv cs.AI · 11h ago · score 92*

This research introduces a critical distinction in indirect prompt injection (IPI) attacks on LLM agents—separating covert successes (undetectable to users) from overt ones (visible in responses)—and demonstrates that current ASR metrics fail to capture the user-facing threat. The proposed ICoA attack technique deliberately crafts injections to return agent control to the user task, achieving significantly higher covert success rates (3.79-12.01 percentage points improvement) by exploiting the ReAct format's behavior patterns, representing a meaningful escalation in the sophistication and danger of IPI threats.

### [Malicious .git Configs Can Make Claude, Codex, Cursor, and Other AI Agents Run Attacker Code](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html)
*The Hacker News · 1h ago · score 92*

Manifold Security disclosed eight vulnerabilities across seven AI coding agents (Claude, Codex, Cursor, and others) where malicious Git configurations can execute arbitrary attacker code on the developer's machine with user privileges and without sandboxing or approval prompts. This is a critical supply-chain attack vector since exploitation only requires the malicious repository to be cloned, making it a high-risk threat to developers using AI-assisted coding tools.

### [AKRASIA: Stealthy Backdoor Attack on Reasoning-based Code LLMs](https://arxiv.org/abs/2609.01023)
*arXiv cs.CR · 11h ago · score 88*

AKRASIA demonstrates a sophisticated inference-time backdoor attack against reasoning-based code LLMs that achieves up to 99.34% success rates while evading state-of-the-art defenses and human inspection by exploiting model unfaithfulness. This attack is particularly concerning for security-critical applications since it injects malicious code execution triggers that remain hidden in reasoning steps, highlighting a significant vulnerability class in reasoning-based LLMs that current defense mechanisms fail to address.

### [Delegation Without Trust: An Empirical Gap Analysis of Identity, Authorization, and Runtime Governance in Multi-Agent LLM Systems](https://arxiv.org/abs/2609.00267)
*arXiv cs.AI · 11h ago · score 92*

This research empirically demonstrates critical gaps in identity and authorization governance across major multi-agent LLM frameworks (LangGraph, CrewAI, AutoGen, MCP), showing that current systems fail to enforce proper privilege delegation boundaries even under prompt-injection attacks. The work establishes a formal threat model with eight security requirements and proposes an authorization broker solution, directly addressing a gap between current practice and the "untrusted model" assumption necessary for production agent deployments.
