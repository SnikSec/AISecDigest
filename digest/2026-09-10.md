### [Detokenization Leaks: Reconstructing Local LLM Outputs From Cache Traces](https://arxiv.org/abs/2609.06674)
*arXiv cs.AI · 11h ago · score 92*

A new cache-based side-channel attack recovers text generated by local LLMs by observing CPU cache activity during the detokenization process, bypassing previous assumptions about deployment-specific conditions. The attack affects default LLM inference pipelines and popular tokenizer implementations across multiple frameworks and model families, creating a broad attack surface for local LLM deployments and agentic systems.

### [CS-Guard: Benchmarking LLM Guardrails for Code Generation Security](https://arxiv.org/abs/2609.09798)
*arXiv cs.CR · 11h ago · score 92*

CS-Guard is a new benchmark that systematically evaluates guardrails protecting LLMs from generating malicious code, testing 9 guardrails across 7 LLMs with text-to-code and code-to-code generation scenarios. The research reveals critical vulnerabilities: guardrails achieve only ~50% defense rates against text-to-code jailbreaks and fail dramatically on code-to-code tasks (14-100% attack success rates), with a novel fictional scenario attack bypassing nearly all tested guardrails.

### [Arbitrary Cipher Attacks Against Large Language Models Do Not Require Fine-Tuning](https://arxiv.org/abs/2609.09553)
*arXiv cs.CR · 11h ago · score 92*

### [functype-mcp-server: MCP `set_functype_version` Package Alias RCE via Unsanitized pnpm install + Dynamic Import](https://github.com/advisories/GHSA-wcjj-9m6g-2fr2)
*GitHub Security Advisories · 15h ago · score 92*

The functype-mcp-server contains a critical RCE vulnerability where the `set_functype_version` MCP tool accepts unsanitized version strings, interpolates them into package specifiers, and installs packages via pnpm without validation. An attacker can exploit npm/pnpm alias syntaxes (file:, npm:, etc.) to inject arbitrary packages, which are then dynamically imported and executed in the MCP server process, achieving full RCE (CVSS 7.8 High).
