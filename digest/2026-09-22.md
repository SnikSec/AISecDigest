## AI Security (5)

### [Your Mailbox Is Mine: Prompt Injection Attacks Against Real-World LLM Email Agents](https://arxiv.org/abs/2507.02699)
*arXiv cs.CR · 11h ago · score 92*

Researchers demonstrate a novel prompt injection attack (ESPI) that exploits LLM email agents by manipulating their interpretation of email protocol states, achieving 73.54% success rates compared to 4-8% for existing template-based attacks. This represents a critical vulnerability in widely-deployed LLM email agents that manage sensitive communications and authentication workflows, requiring immediate attention from both defenders and LLM application developers.

### [Speed Kills: Exploring Confused Deputy Attacks Through Edge AI Accelerators](https://arxiv.org/abs/2605.17707)
*arXiv cs.CR · 11h ago · score 92*

This research reveals confused deputy attacks (CDAs) are feasible on 6 out of 7 major AI accelerators from vendors including Google, NVIDIA, and AWS, affecting over 100 million devices by exploiting semantic gaps between AIAs and OS security mechanisms. The study introduces DeputyHunt, an LLM-assisted framework that systematically identifies AIA-specific vulnerabilities, with findings already acknowledged by vendors and assigned CVE-2025-664.

### [Training-Free Refusal of MCP Exploits via Retrieval-Augmented Generation](https://arxiv.org/abs/2605.11217)
*arXiv cs.CR · 11h ago · score 82*

This paper addresses a critical vulnerability in MCP-enabled LLMs: falsely benign prompt injection attacks that bypass existing guardrails by disguising malicious tool-use requests as innocent queries. The authors propose RAG-Pref, a training-free alignment method that achieves 3.7x improvement in attack refusal rates compared to standard fine-tuning approaches, providing practical defense mechanisms for agentic AI systems.

### [@aborruso/ckan-mcp-server has SSRF via DNS-name → internal IP — incomplete fix of CVE-2026-53509](https://github.com/advisories/GHSA-798p-78g2-v556)
*GitHub Security Advisories · 1h ago · score 82*

The SSRF guard in @aborruso/ckan-mcp-server fails to resolve DNS names, allowing attackers to bypass the protection by supplying hostnames that resolve to internal IP addresses like loopback and cloud metadata endpoints (169.254.169.254). This is a complete bypass of the CVE-2026-53509 fix still present in the current version 0.4.107, with no patch available, affecting all self-hosted deployments using unauthenticated HTTP transport.

### [@roomi-fields/notebooklm-mcp has a path traversal in vault.batch tool that allows arbitrary file write outside intended vault directory](https://github.com/advisories/GHSA-jjhp-8crj-mppq)
*GitHub Security Advisories · 1h ago · score 82*

A path traversal vulnerability in the roomi-fields/notebooklm-mcp vault.batch tool allows arbitrary file writes outside the intended vault directory through unsanitized vault_dir and slug_prefix parameters. This vulnerability is particularly dangerous when the MCP server is driven by an LLM that has processed untrusted content (prompt injection), enabling attackers to plant files in sensitive locations like autostart folders.
