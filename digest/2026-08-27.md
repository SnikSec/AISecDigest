## AI Security (5)

### [EVOMAL: Self-Poisoning in Self-Evolving Coding Agents](https://arxiv.org/abs/2608.25776)
*arXiv cs.CR · 17h ago · score 92*

EVOMAL demonstrates a critical self-poisoning vulnerability in self-evolving LLM coding agents that automatically generate and reuse tools from shared skill libraries. When agents imitate malicious skills as templates, they can author and execute new malicious skills that self-propagate through the library, creating a worm-like attack that persists even after the original planted skills are removed, with observed success rates of 20-87% depending on the model and attack configuration.

### [APPA: Recoverable Information-Flow Control for Real-World LLM Agents](https://arxiv.org/abs/2607.24625)
*arXiv cs.CR · 17h ago · score 85*

APPA proposes a recoverable information-flow control system for LLM agents that replaces traditional abort-on-taint approaches with policy-governed recovery mechanisms, enabling agents to safely handle mixed private and untrusted data through dual-phase validation at tool dispatch and context admission. The system addresses critical vulnerabilities including prompt injection, data exfiltration, and confused-deputy attacks while maintaining practical usability through gradual security typing and trajectory confinement, proving key safety invariants like no-laundering and branch isolation.

### [ADVERSA: Measuring Multi-Turn Guardrail Degradation and Judge Reliability in Large Language Models](https://arxiv.org/abs/2603.10068)
*arXiv cs.AI · 17h ago · score 82*

ADVERSA is a new red-teaming framework that measures LLM guardrail degradation through multi-turn adversarial conversations rather than single-prompt jailbreak attempts, using a fine-tuned 70B attacker model to eliminate safety refusals that compromise attack reliability. The research reveals that frontier models (Claude, Gemini, GPT) experience a 26.7% jailbreak rate concentrated in early rounds, and highlights critical evaluation gaps including judge reliability variance and attacker drift—findings that directly impact how organizations should approach LLM safety assessment.

### [SkillShield: Prompt-Space Security Skills for LLM Coding Agents](https://arxiv.org/abs/2608.25817)
*arXiv cs.CR · 17h ago · score 82*

SkillShield is a system-prompt defense mechanism that injects synthesized security skills into LLM coding agents to prevent malicious code execution and protect against prompt-based attacks without requiring separate classifiers or runtime monitoring. The approach demonstrates significant effectiveness across multiple LLMs, reducing malware-generation severity and attack success rates comparable to existing solutions like Llama Guard 3 while avoiding the deployment constraints of weight-level alignment or auxiliary classification components.

### [NeuronGuard: Robust LLM Safety Alignment via Ablation-Aware Safety Signal Redistribution](https://arxiv.org/abs/2608.23959)
*arXiv cs.AI · 17h ago · score 82*

NeuronGuard presents a fine-tuning defense that hardens LLMs against both jailbreak and neuron-level pruning attacks by redistributing safety signals across a broader set of neurons, with formal guarantees reducing attack success rate upper bounds. The approach uses ablation-aware training with KL-divergence regularization to maintain robustness while preserving downstream task utility, demonstrating near-zero attack success rates across multiple LLMs and attack strategies.
