## AI Security (6)

### [The Chronos Vulnerability: A Taxonomy of Temporal Persistence and Memory-Based Deception in Agentic AI](https://arxiv.org/abs/2607.19433)
*arXiv cs.AI · 9h ago · score 92*

The Chronos Vulnerability describes memory-based attacks on stateful autonomous agents where attackers can compromise an agent's internal beliefs through Memory Injection Attacks (MINJA) and sleeper agents, decoupling the attack from when damage occurs. This research formalizes the threat model for persistence-based attacks on agentic AI systems and proposes defense-in-depth strategies including trajectory guardrails, formal verification, memory consensus mechanisms, and TEE-based architectures.

### [DARWIN: Evolving Jailbreak Adversary and Guardrail for LLM Safety Evaluation and Protection](https://arxiv.org/abs/2607.19829)
*arXiv cs.CR · 9h ago · score 92*

DARWIN presents an evolutionary attack-defense framework where jailbreak attacks continuously evolve through strategy discovery, mutation, and composition, achieving near-universal attack success rates on frontier LLMs including near 100% on DeepSeek-V4-Pro and GPT-4.5. The paper also introduces DARWIN-Guard, an online adversarial training approach that iteratively hardens LLM guardrails against emerging evolved attacks, representing a significant advancement in both LLM safety evaluation methodology and defensive capabilities.

### [LiteLLM: MCP Authentication Bypass via OAuth2 Passthrough Fallback](https://github.com/advisories/GHSA-7488-6r32-c95q)
*GitHub Security Advisories · 14h ago · score 92*

LiteLLM's MCP Streamable HTTP endpoint contained an authentication bypass allowing unauthenticated attackers to establish authenticated MCP sessions using arbitrary Bearer tokens due to a flawed OAuth2 passthrough fallback mechanism. This vulnerability enabled attackers to list, call configured MCP tools, and access connected services exposed through MCP without valid credentials, affecting versions prior to 1.84.0.

### [ChannelGuard: Safe Models Do Not Compose into Safe Multi-Agent Systems](https://arxiv.org/abs/2607.19430)
*arXiv cs.AI · 9h ago · score 92*

This paper reveals that multi-agent LLM systems are vulnerable at inter-agent communication channels, with apparent safety depending heavily on opaque provider-side filtering rather than inherent model alignment. ChannelGuard is proposed as a training-free defense framework using information bottlenecks and embedding-based detection at each agent boundary, achieving consistent tool-poisoning protection across different model backends without adding inference calls.

### [ChainWatch: A Kill Chain-Aligned Sequential Detection Framework for Multi-Step Attacks in MCP-Based AI Agent Systems](https://arxiv.org/abs/2607.19432)
*arXiv cs.AI · 9h ago · score 85*

ChainWatch proposes a sequential detection framework using Hidden Markov Models and kill-chain analysis to identify multi-step attacks in MCP-based AI agent systems, addressing a critical gap where attackers compose individually benign tool invocations into malicious sequences. This work is highly relevant for securing agent systems that integrate external tools through the Model Context Protocol, as it demonstrates detection of sophisticated attacks that evade traditional per-call inspection mechanisms.

### [n8n: "Allowed HTTP Request Domains" Restriction Bypass via AI Agents MCP Connector](https://github.com/advisories/GHSA-h44j-f5r5-ph73)
*GitHub Security Advisories · 15h ago · score 82*

n8n's AI Agents feature fails to enforce "Allowed HTTP Request Domains" restrictions on credentials, allowing member-level users to exfiltrate secrets to attacker-controlled servers via MCP tool URLs. This vulnerability affects instances with AI Agents enabled and shared credentials, with patches available in versions 2.28.1 and 2.27.4.
